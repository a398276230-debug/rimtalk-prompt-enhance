# 天气与环境事件增强功能

## 概述

本功能实现了对 RimWorld 中天气变化和游戏状况（GameCondition）的自动捕获，将这些环境事件记录到事件系统中，为 AI 提供更丰富的环境上下文信息。

## 核心功能

### 1. 天气变化捕获

**实现文件**: [`WeatherTransitionPatch.cs`](../Source/Patches/WeatherTransitionPatch.cs)

通过 Harmony 补丁拦截 `WeatherManager.TransitionTo` 方法，当天气发生变化时自动创建事件记录。

**捕获信息**:
- 天气名称和描述
- 是否会下雨/下雪
- 风速强度
- 移动速度影响
- 预计持续时间

**示例输出**:
```
🌤️ Weather Changed: Thunderstorm
Heavy rain with lightning strikes.
Rain rate: 1.0
Movement speed factor: 0.9
```

### 2. 游戏状况捕获

**实现文件**: [`GameConditionCapturePatch.cs`](../Source/Patches/GameConditionCapturePatch.cs)

通过两个 Harmony 补丁实现：

1. **`GameConditionRegisterPatch`**: 拦截 `GameConditionManager.RegisterCondition`，捕获状况开始事件
2. **`GameConditionEndPatch`**: 拦截 `GameCondition.End`，捕获状况结束事件

**捕获的状况类型**（自动捕获所有 `displayOnUI = true` 的状况）:
- 热浪 (HeatWave)
- 寒潮 (ColdSnap)
- 毒雾 (ToxicFallout)
- 日食 (Eclipse)
- 极光 (Aurora)
- 太阳耀斑 (SolarFlare)
- 闪电风暴 (Flashstorm)
- 火山冬天 (VolcanicWinter)
- 心灵波动 (PsychicEmanation)
- **异常黑暗 (UnnaturalDarkness)** - Anomaly DLC
- **黑荆迷雾** - Anomaly DLC
- 以及任何 DLC 或 Mod 添加的 GameCondition

**捕获信息**:
- 状况名称和描述
- 预计持续时间
- 温度影响（静态偏移值）
- 状况结束时的实际持续时间

**示例输出**:
```
⚠️ Heat Wave
Extreme heat makes outdoor activities dangerous.
Expected duration: 3 days
Temperature effect: +20°C
```

## 技术实现

### 事件去重机制

由于某些 GameCondition 开始时也会发送信件（Letter），为避免重复捕获，实现了去重机制：

**实现位置**: [`EventCaptureService.cs`](../Source/Services/EventCaptureService.cs)

```csharp
private static HashSet<string> _capturedGameConditionLabels = new HashSet<string>();

public static void MarkGameConditionCaptured(string label)
{
    if (!string.IsNullOrEmpty(label))
        _capturedGameConditionLabels.Add(label.ToLower());
}

private static bool IsGameConditionAlreadyCaptured(string title)
{
    // 检查标题是否与已捕获的 GameCondition 标签匹配
}
```

工作流程：
1. GameCondition 被捕获时，调用 `MarkGameConditionCaptured()` 标记其标签
2. Archive 系统捕获信件时，调用 `IsGameConditionAlreadyCaptured()` 检查是否重复
3. 如果是重复的，跳过信件捕获，避免出现两条相同事件

### 优先级智能判断

优先级判断采用多层策略，不依赖硬编码的 defName 穷举：

1. **温度影响判断**:
   - 温度偏移 > 15°C → 紧急 (Urgent)
   - 温度偏移 > 10°C → 高 (High)

2. **状况类型判断**:
   - 检查 `conditionClass` 类型名称
   - 心灵类事件 → 紧急 (Urgent)

3. **关键词匹配**:
   - 紧急关键词: toxic, fallout, psychic, darkness, anomaly, death, plague...
   - 高优先级关键词: heatwave, coldsnap, blizzard, storm, aurora...

4. **后备判断**:
   - 有任何温度影响 → 普通 (Normal)
   - 其他 → 低 (Low)

## 设计决策

### 为什么不显示实时温度？

最初的设计包含了当前室外温度的显示，但发现问题：
- 事件创建后，描述文本是静态的，无法实时更新
- 显示创建时的温度会造成误导，因为用户可能在之后查看该事件

**解决方案**: 只显示温度偏移值（静态属性），不显示实时温度。

### 为什么需要去重？

RimWorld 的某些 GameCondition 开始时会同时：
1. 注册 GameCondition（被 `GameConditionRegisterPatch` 捕获）
2. 发送信件到 Archive（被 `ArchiveCapturePatch` 捕获）

这会导致同一事件出现两次。通过标记已捕获的 GameCondition 标签，可以让 Archive 系统跳过这些重复的信件。

### 为什么优先级判断使用多层策略？

单纯的 defName 穷举法有以下问题：
- 无法覆盖所有 DLC 和 Mod 添加的状况
- 需要持续维护关键词列表

多层策略的优势：
1. 温度影响是客观可测量的，适用于所有温度相关状况
2. conditionClass 类型检查可以识别特定类别的状况
3. 关键词匹配作为后备，覆盖常见情况
4. 未知状况仍会被捕获，只是优先级较低

## 后续优化建议

1. **实时状态查询**: 可以考虑添加一个方法，让 AI 能主动查询当前的环境状态，而不是依赖事件记录

2. **状况严重程度**: 某些状况有严重程度变化（如心灵影响的强度），可以考虑捕获这些变化

3. **多地图支持**: 目前只捕获当前地图的状况，可以扩展到支持所有玩家地图

4. **天气预报**: 可以尝试分析天气模式，提供简单的天气预测
